## Architecture and contract

1. Add `transport_fuels_fetcher.py` containing a small adapter registry of ten explicit country functions. Reuse requests, pandas, BeautifulSoup; add openpyxl and xlrd for real XLSX/XLS, and lxml if pandas.read_html is used. Avoid Selenium, new databases, queue frameworks, paid services, or a second scheduler.
2. Each adapter fetches official source files, checks product/unit/geography labels, parses native monthly levels, and returns a normalized table plus provenance. Canonical columns are `date,gasoline,jet_fuel,diesel,native_unit` as expected by the existing publisher, NOT the alternative `_level` headings in the reconstruction guide.
3. Bootstrap a continuous July2020-through-latest-complete-month history from original sources; there are currently no persisted source-level files. Existing chart begins July2021 and cannot supply its prior-year input history. Never backsolve July2020-June2021 from YoY. Full historical re-fetch is simplest and catches revisions. For annual files request all years from 2020 through current year, using real published links rather than assuming every current-year file exists. Full-history downloads remain small enough; do not build an incremental cache prematurely.
4. Build all-ten-country manifest in a temporary directory. Each source exception creates `{status:error,message:...}`; a successful entry supplies normalized CSV, exact official URLs, vintage, and validation_note identifying final native month and values and actual source header labels. Pass once to existing `scripts/update_transport_fuels.apply_manifest`. It already validates conversions, gaps, duplicates, missing/nonfinite/negative observations, units, gross scale changes, truncation, and independent failures; it recalculates rates and YoY and publishes the bundle. Keep this sole writer.
5. Integrate one `fetch_transport_fuels_dashboard()` call into `data_fetcher.fetch_all()` before final metadata, with its own exception boundary so no other macro feeds are blocked. HTTP connect/read timeout roughly 10/45 seconds and at most 2 retries for transient 429/5xx/timeouts. Keep overall work bounded under current 45-minute job. Running countries sequentially initially is acceptable; if parallel, separate requests sessions per country and publish only after collection.
6. Existing refresh-data.yml keeps 14:00, 16:00, 23:30 UTC weekdays. Extend current git staging to data/ AND explicit transport data.json, refresh-status.json, both standardized CSVs, source-levels/*.csv. Do not stage raw giant workbook files. Ensure valid outputs and error statuses commit on partial source failure. Emit country results in job summary/logs, and use a final post-commit failure/report step if desired; do not fail before committing good countries. Keep existing no-force pull/rebase/push behavior.

## Publication, revisions, provenance and status

- Recompute all full-history levels and YoY each successful run, including revisions affecting later same-month YoY. No append-only shortcut. Full-history endpoint that returns less than current history must fail; do not erase old chart tail.
- Add source checksums of downloaded raw bytes, retrieval time and exact final URLs to manifest/provenance if practical; publisher currently stores only normalized extract checksum. Retain raw downloads as short-lived workflow artifact on failure if useful, not committed to public static folder. If release date cannot be found, say retrieved <date>, release date not supplied; never fabricate release date from today's clock.
- `last_attempt_at` always updates; `last_success_at` only after validated official data, even if unchanged; `last_data_change_at` only when data values change. Failed country retains exact prior rows, source metadata, catalog values and native extracts. Set refresh-status owner/method/schedule metadata to GitHub ETL and remove stale automation identifiers. Errors must identify stage/country/source without secrets.
- Current UI 48-hour overdue threshold will falsely warn every Sunday with weekday schedule. Use 96 hours for a simple weekend-safe threshold, or an explicit next scheduled check. Change documentation accordingly.
- An unpublished tail consists of all three missing values; a partial final month is not silently complete. Do not treat printed zero as blank without publisher evidence. No third-party substitutions or inferred filler values. Preserve independent country cutoffs; never sum asynchronous latest rows into global total.
- Keep native-unit conversion function/factors unchanged. Existing validator permits up to 10x overlap changes; add reporting of largest revisions for review, not an arbitrary permanent rejection of plausible revisions.
